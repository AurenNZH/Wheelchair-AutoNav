Operator Intent Injector Decision Log
=====================================

2026-08-01T20:36:27+01:00 — Design milestone
The injector is deliberately placed in wheelchair_shared_control and not in
wheelchair_simulation. Its only output is the existing OperatorIntent contract,
so it remains independent of Gazebo, robot geometry, simulated sensors, and
motion. The first version exposes only released and straight-forward presets:
SLOW and STOP remain safety-supervisor decisions rather than commands that a
test tool can claim. A finite 30-second wall-time lease retains deadman meaning
and prevents an unattended preset from remaining active indefinitely.

The installed ROS 2 Foxy bag player does not publish /clock. Changing the
production supervisor to accept old timestamps would add a replay exception to
safety-critical code, so a replay-only adapter instead republishes recorded
occupancy grids with receipt timestamps. It forwards maps only when bag data
arrives, preserving stale-map failure when playback pauses or ends.

2026-08-01T20:39:03+01:00 — Implementation milestone
The implementation uses three small nodes rather than combining replay,
intent, and reporting into one scenario runner. This keeps the production
supervisor as the system under test and makes each failure attributable: the
injector owns operator intent, the restamper owns the Foxy compatibility
boundary, and the monitor owns human-readable output. The replay launch starts
the supervisor directly instead of including the normal UDP bridge, and it
does not import or modify the Gazebo package. Configuration values that affect
message identity, cadence, or lease semantics require a restart; only the
released/forward command changes dynamically during a run.

2026-08-01T20:51:38+01:00 — Testing milestone
Verification was layered so a passing unit test could not hide wiring errors.
The two affected ROS packages built successfully and all 21 shared-control
tests passed, including seven new injector/replay tests. An isolated live ROS
graph then demonstrated CLEAR for empty maps, SLOW with the configured 0.35
forward limit for an obstacle in the slow region, and STOP for a closer
obstacle. Stopping map publication produced stale_map, and a shortened
three-second lease produced deadman_released. Graph inspection showed only the
injector, restamper, supervisor, and monitor, with no velocity topics. Static
diff and style checks also confirmed that no Gazebo-owned file was modified.

2026-08-01T20:52:17+01:00 — Handoff milestone
The operator workflow is intentionally three explicit terminal actions: start
the decision-only launch, play only the two remapped map topics, and set the
injector command. Keeping the bag process outside the launch makes the bag
path, playback rate, looping, and stopping visible to the tester and avoids
embedding external process lifecycle policy in ROS launch. The installed
package exposes the three new executables and the replay launch arguments, and
the repository remains uncommitted so the owner can review the complete diff.

2026-08-03T19:38:11+01:00 — Replay diagnosis milestone
Testing with the three recorded bags showed that intent changes are delivered:
forward intent changed the supervisor output to surround_proximity and lease
expiry changed it to deadman_released. The apparent lack of response came from
two copies of each decision log and prerequisite failures dominating the
console. The bags average about 4.3 Hz but contain individual map gaps between
1.1 and 1.7 seconds, so the production-oriented 0.30-second timeout repeatedly
reported stale_map. Replay uses a 2.0-second decision-inspection tolerance while
the production default remains unchanged. The console separately shows semantic
intent, map health, and decision states so a blocked decision no longer hides
whether a new intent arrived.

2026-08-03T19:53:50+01:00 — Replay diagnostics verification milestone
The operator-facing monitor now treats sequence and timestamp updates as
heartbeats, logging only semantic intent and decision changes. It watches map
receipt independently so map readiness remains visible even when the supervisor
is stopped for another reason. Intent publisher and subscriber history were
reduced to one sample to prevent startup backlog from appearing as stale input.
The package rebuilt successfully and all 24 tests passed. A looped clear bag
then produced MAPS READY, showed FORWARD followed by surround_proximity, and
showed the five-second diagnostic lease return to RELEASED and deadman_released.
No intermittent stale-map transition or duplicate internal decision appeared.

2026-08-03T22:09:15+01:00 — Front-only scope milestone
The supervisor contract is intentionally narrowed to /front_costmap. The full
/local_obstacles grid remains valuable for RViz, lidar-reflection, self-filter,
and future coverage work, but rear and side cells no longer veto a forward
operator request. Keeping one obstacle input makes production and replay test
the same policy and removes surround_proximity rather than hiding it in replay.
This accepts that obstacles initially beside or behind the chair are outside
the current project scope. Straight and bounded-right policy remain unchanged;
left/right injector expansion is deferred to a separately calibrated change.

Applying the proposed front-only policy to the existing clear bag still yielded
obstacle_stop at a swept distance of zero in all 113 frames. The recording also
contains forward-sector self-returns, so eliminating the rear-map dependency is
not expected to make that bag CLEAR. A shielded, stationary re-recording will
separate the map-quality issue from the supervisor-policy issue before a fixed
lidar hood is designed.

2026-08-03T22:16:27+01:00 — Front-only verification milestone
The shared-control package rebuilt successfully and all 24 tests passed after
removing the full-surround input. An isolated live replay published only the
recorded /front_costmap through the restamper: the monitor reached MAP READY
without /local_obstacles, forward intent produced obstacle_stop from the known
near-field returns, and the five-second lease returned to deadman_released.
Stopping that single map stream produced stale_map and MAP STALE after the
two-second replay timeout. No surround_proximity decision was emitted, and no
Gazebo-owned file was changed.

2026-08-07T18:46:29+01:00 — Centred geometry and cell-support milestone
The measured 0.80 m base is centred on base_link, so shared control now models
0.40 m in front and 0.40 m behind while retaining 0.70 m STOP and 1.20 m SLOW
travel distances. The artifact shadow now requires at least three post-mask
returns in every occupied front cell; its explicitly configured artifact halo
retains the stricter fifteen-return rule. This separates general single-return
noise rejection from the evidence already gathered for persistent AIRY
artifacts, and deliberately leaves the raw front map unchanged for comparison.

Five replay residual cells are published as labelled, static RViz diagnostics;
they do not alter either map. Reprocessing the raw clouds with the new rules
made clear_lidar_fix_01 CLEAR in 123/123 frames and clear_lidar_fix_02 CLEAR in
158/159 frames. The remaining STOP was R1 at cell (6, 1), which exceeded the
fifteen-return halo threshold in one frame. This is evidence for a fresh
clear_lidar_fix_03 recording, not justification to weaken the halo threshold.

2026-08-07T19:19:57+01:00 — R1 height refinement
Inspection of clear_lidar_fix_03 located the R1 survivors in the correct XY
cell but immediately above its 0.420 m Z ceiling. The R1 ceiling alone was
raised to 0.430 m; neighbouring cells, the chassis self-filter, the global
three-point rule, and the local fifteen-point rule remain unchanged. This is a
narrow recorded-evidence adjustment rather than a broader obstacle-policy
relaxation, and still requires a physical target gate before promotion.
